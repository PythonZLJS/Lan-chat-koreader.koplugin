NEIGHBOUR CHAT 7.1 - SECURITY AND LIMITS

The native reader accesses a loopback-only bridge with Host/peer validation,
a 256-bit bearer capability, and rejection of Origin-bearing control requests.
The key stays in a private local file; passwords are never included in URLs,
shell commands or KOReader settings. No remote HTML/scripts run in the reader.

Chat traffic uses HTTPS with a device-specific certificate. Joining verifies
its SHA-256 pin and validity dates before credentials are sent. Hosts are
literal private/loopback IPv4 addresses; redirects are not followed. The Wi-Fi
listener accepts private-network clients and has connection/body/time limits.
API cookies are HttpOnly/Secure, rotate at login, expire after 12 hours and
are protected by CSRF. The bridge uses a separate capability, not those cookies.

Password hashing remains Argon2id (19 MiB, two iterations, one lane), with
bounded concurrency and support for old Werkzeug scrypt/PBKDF2 passwords.
New accounts need a join code and host approval. Disabled/revoked accounts
lose access. The server filters private messages, search results and files by
room and ownership/recipient, not by the client UI.
Room membership is host-controlled. Deleted room public history is archived
under an internal identifier, so recreating a name cannot expose it.
Kick/ban/unban increment account session versions; unban cannot revive an old
cookie. IP bans use the actual peer address, not forwarded headers, and persist.
Only administrators receive users' IP addresses through host tools.
Recent hosts save only private address/certificate-pin pairs (up to eight),
never passwords. Forget removes both. Changed pins cannot silently reconnect. Retry keys prevent duplicate sends.

The compact build statically links SQLite C via pinned go-sqlite3 v1.14.53;
SQLite extension loading is disabled. It keeps old SQLite databases and the
existing app-level encryption formats compatible. Go 1.27.4 replaces 1.27.3,
which the final scan flagged for GO-2026-6859. The build checks the Go source
and exact ARM binary against the current official vulnerability database.
A clean Go scan is not an audit of all C code or proof of zero vulnerabilities.

File transfers stream in bounded buffers with size/quota checks. Uploads chosen
by the user must resolve inside Kindle storage. Downloads have unique names,
are bounded to the reported size and never overwrite existing files. They are
ordinary files OUTSIDE saved-content encryption. Optional saved-content
encryption still protects stored chat/file contents with XChaCha20-Poly1305;
metadata remains visible. Unlocked hosts can read messages: this is not
end-to-end encryption. Physical/USB access can expose local files and keys.

Backups remain in the plugin's private data/backups folder, including
preserved legacy snapshots migrated from older sibling locations.
Automatic migration copies keep their installation ID/encryption association.
Historical uninstall/PC backups are not retroactively encrypted by another
installation. Removing the plugin preserves live data, backups and the log.

Network work runs in a bounded service worker. State reads are cached, and
unchanged state uses conditional responses. Hide retains the session; explicit
Disconnect clears it; Stop bypasses busy jobs, cancels requests and ends the
service. Sleep can disconnect Wi-Fi and session expiry still applies. No
power-management override or stored-password auto-login is added.

Physical Kindle/KOReader testing is still required. Contract tests with widget
stubs do not establish actual screen, gesture, sleep or battery behaviour.

7.0 DISCOVERY AND OWNER ROLE
Discovery is an optional, unencrypted UDP responder on port 8002. It opens only
while local hosting is running and the owner explicitly enables discovery.
Turning it off closes that socket; it does not stop HTTPS on port 8000 or
prevent independent scans/manual reconnects. No advertising setting is saved
across service restarts. All discovery controls require the loopback capability.
The responder accepts private/loopback IPv4 queries only, validates a protocol
marker and 128-bit scan nonce, caps datagrams at 512 bytes, rate limits responses
and respects IP bans. Responses reveal only the chosen name and chat port.
A client sends a single bounded broadcast round, keeps at most 20 results and
never sweeps subnet IPs/TCP ports. Source addresses supply the actual host IP;
claimed addresses/other ports, unrelated nonces and oversized data are ignored.
UDP discovery is not authentication. First joins still probe TLS, require a
check-code comparison and then pin the actual HTTPS certificate. Saved hosts
retain their existing pin. Names cannot confer trust or bypass account approval.
Local Host uses an internal admin session for the Kindle owner, guarded by the
private KOReader capability. No public owner-login or discovery-control endpoint
was added; remote guests still need accounts/passwords and remain regular users.

7.1 REVIEW FIXES
See SECURITY-REVIEW.txt for concrete findings and regression cases. Context
identifiers bind queued UI work to a chat/account/room and are not credentials.
Login resets identity-dependent caches. Public sends/uploads check the reader's
room hint inside their database transaction. IP bans remain independent for
each banned account. Cookie rotation consumes a live old cookie once; a single
reserved internal owner session permits local recovery under LAN session churn.
Large combined state previews are bounded below Lua's response cap; no stored
content is removed by that preview limit.
