NEIGHBOUR CHAT 7.1 - BUG AND SECURITY REVIEW
Date: 2026-11-11
Scope: current KOReader plugin and shared Go service, especially new discovery,
local owner permissions, session lifecycle, room/file access and delayed GUI work.
This is a targeted source review with regression tests, not an independent
penetration test or a guarantee that no other vulnerabilities exist.

FIXED FINDINGS
1. High (privacy): cached private content survived an account switch.
   A successful login while already connected reused the old identity, message
   page, search/inbox/account data and older-page cursor. Login now invalidates
   all identity-dependent caches before reloading the actual authenticated user.
   Test: TestAccountSwitchDropsPrivateCachesAndRejectsOldActions.

2. High (privacy): drafts, selected recipient IDs and open dialogs were not tied
   to their chat/account/room. A delayed editor or login form could act on a
   different host; the same numeric user ID can identify another person there.
   State now has a non-credential context generation. Account/host/room changes
   clear local drafts/recipients/retry keys, guard dialogs/menus/file selections,
   and reject stale queued actions. Open editors cannot restore a stale draft.
   Tests: four new Lua context/follow-up tests and the stale-action Go test.

3. Medium (privacy): a host moving a user before their next poll could redirect
   an already-composed public message/file into a different room. KOReader now
   includes a room hint; the server checks membership inside the storage
   transaction and rejects stale public destinations. Private delivery still
   works across rooms. Test: TestRoomHintRejectsMessagesAndFilesAfterUnseenRoomMove.

4. Medium: room deletion used case-insensitive lookup but case-sensitive history
   updates. Deleting a differently capitalized name could leave members/history
   behind and reveal public content after recreating that room. Deletion now
   resolves the canonical existing name inside the transaction before moving
   members and archiving public messages/files. The room-isolation/recreation
   test now deletes with deliberately mixed capitalization.

5. Medium: one IP ban overwrote another account's rule for the same address.
   Unbanning the second account then removed the first account's IP restriction.
   The ban key is now (IP, account); legacy rules migrate transactionally and
   unban removes only that account's rules. Test:
   TestOverlappingIPBansAndLegacyBanMigration.

6. Medium (availability): simultaneous successful logins could rotate the same
   old cookie repeatedly, bypassing the intended session-count bound. Rotation
   now atomically verifies and consumes the still-live old session exactly once.
   Test: TestConcurrentSessionRotationCannotForkOneCookie (24 concurrent calls).

7. Medium (availability): local owner login depended on creating an anonymous
   network session. Guest rate limits or a full session table could block the
   Kindle owner from administering their own server. There is now one reserved,
   replaceable internal owner slot, without any public login-bypass endpoint.
   Its ownership follows cookie rotation; regular-session limits remain bounded.
   Test: TestLocalOwnerCanRecoverUnderFullSessionTable (512 occupied slots).

8. Low (availability/UI): an unexpected discovery receive error could leave a
   dead socket/status reported as discovery ON. The responder always closes its
   socket; status checks detect termination and enabling it can recover. Scans
   explicitly check cancellation/deadlines and discovery writes have a timeout.
   Test: TestDiscoverySocketFailureIsReportedAndCanRestart.

9. Low (GUI correctness): a rejected action still scheduled a follow-up reader
   callback, which could interpret unrelated state as the requested result.
   Actions now report acceptance and failed requests never start that callback.
   Test: test_rejected_action_does_not_run_followup_on_unrelated_state.

10. Medium (availability): combined long Unicode search/inbox/chat results and
    account metadata could exceed Lua's 512 KiB response cap, leaving the UI
    unable to read its state. Serialized previews now stay below 480 KiB,
    explicitly report trimming and preserve the underlying caches/database.
    Test: TestLargeCombinedReaderCachesStayWithinLuaResponseLimit.

DEPENDENCY REVIEW
The shipped go-sqlite3 v1.14.53 actually bundles SQLite 3.54.1 (checked in the
amalgamation header). The upstream release includes the 32-bit heap-overflow
fix present in SQLite 3.54.1; no dependency downgrade was made for Kindle size.
Primary references checked on the review date:
https://github.com/mattn/go-sqlite3/releases/tag/v1.14.53
https://sqlite.org/changes.html
Go 1.27.4 and pinned modules are checked using official govulncheck, including
the actual ARM binary. Those checks do not fully audit the bundled C engine.

LIMITS THAT REMAIN BY DESIGN
Discovery is unauthenticated and reveals a chat name/address while enabled.
Turning it off hides app discovery; it cannot hide a running HTTPS server from
independent port scans or revoke known addresses. Accounts, approval and bans
control access. First joins still require comparing the actual TLS check code.
Chat is not end-to-end encrypted: the hosting device can read it. Physical USB
access or another privileged jailbreak plugin can expose local files/keys.
Downloads are ordinary files outside optional saved-content encryption.
Very large native previews may be shortened, with a notice; saved content is
not deleted by the preview limit. Older hosts must also upgrade to obtain the
new transactional room-hint and moderation protections.
Actual Kindle 12th generation firmware 5.20.2 rendering, Wi-Fi broadcast,
suspend/resume and battery behavior have not been physically tested.

VALIDATION
Go vet and the full regression suite passed (52 Go test functions, including
24 simultaneous cookie rotations; optional old web-preview test remains skipped).
27 LuaJIT UI/protocol contract tests passed.
Official govulncheck reported No vulnerabilities found for both the source and
exact final ARM executable. ZIP content, checksum, permissions, static ELF and
source-to-package agreement are checked separately.
The optional Go race-detector run did NOT complete: the Windows ThreadSanitizer
runtime failed to map shadow memory (error 87). Therefore no race-detector clean
result is claimed. Ordinary concurrent regression tests did run successfully.
Physical Kindle behavior and SQLite C internals were not instrumented by this
review. These are material limits of the validation, not proof of no other bugs.
